# Engineering Principles for Clydebank Software Co.

> **Fictional demo content.** Clydebank Software Co. is not a real organisation.

## Principles

1. Keep the main branch releasable.
2. Prefer small changes with a clear rollback path.
3. Automate checks that prevent repeat failures.
4. Keep developer workflows fast enough to use every day.
5. Record operational ownership before a service becomes critical.
6. Treat generated code as code that the team owns.

## Review questions

* Does the proposal reduce or increase feedback time?
* Can the team test the change without a live network dependency?
* Who maintains the workflow when the original author is unavailable?
* What evidence proves the change is better than the current path?
